# Model and Training Setup

This document tracks the model setup implemented in the current repository for the fall-detection benchmark. It is written to support the thesis methods section: each model is introduced by its role, input representation, training setup, key parameters, and scoring method.

The code paths described here are current as of this repository state:

- model definitions: `src/models/`
- training entry points: `src/training/`
- engineered features: `src/training/extract_features.py`
- evaluation and thresholding: `src/training/evaluation.py`, `src/training/thresholds.py`

## Benchmark Setup

The main benchmark compares supervised fall classification against time-series anomaly detection (TSAD) using the same processed window artifacts.

Primary processed-data settings:

| Setting | Current setup |
| --- | --- |
| Datasets | SisFall, FallAllD, UMAFall, UP-FALL |
| Main sampling rate | 20 Hz resampled dataset variants |
| Main window duration | 2 seconds |
| Main overlap | 50% |
| Main raw input shape | `40 x 3` triaxial accelerometer window |
| Main flattened input size | `120` values |
| Split protocol for final benchmark | Subject-wise 5-fold cross-validation |
| Model seed in runbook | `42` |
| Run root | `runs/benchmark` |

Window duration is controlled in seconds, not samples. At 20 Hz, the default 2 second window produces 40 time steps. Native-rate and window-duration sensitivity experiments keep the same training logic but can change the number of time steps.

## Preprocessing Used by Models

The processed datasets are generated by `src.preprocessing.run_pipeline_2` and `src.preprocessing.run_cv_pipeline`.

The preprocessing sequence is:

1. Load trial-level interim accelerometer data.
2. Optionally resample each trial using `scipy.signal.resample_poly`.
3. Build subject-disjoint splits. The final benchmark uses `subject_kfold` with `n_folds=5`.
4. Generate fixed-duration sliding windows with 50% overlap by default.
5. Label each window using the fall-region overlap rule.
6. Fit z-score normalization statistics on training windows only.
7. Export separate `classification` and `tsad` processed views.

Window labeling uses the signal-vector-magnitude peak as the estimated fall impact point in fall trials. A fall region is defined as +/- 1.0 second around this impact point. A window is labelled as fall if it comes from a fall trial and overlaps more than 60% of this fall region.

The classification view keeps both fall and non-fall training windows. Its normalization statistics are fitted on all classification training windows. The TSAD view keeps only normal windows in the training split and fits normalization statistics only on eligible normal training windows. Validation and test splits retain labelled fall and non-fall windows so that anomaly scores can be evaluated against the same binary target.

## Shared Evaluation Protocol

All models produce a continuous score where larger values mean more fall-like or more anomalous:

- supervised classifiers output a fall probability or probability-like score;
- Isolation Forest outputs the negative decision function;
- autoencoders output mean squared reconstruction error.

The operating threshold is selected on the validation split by maximizing F1 over the unique validation scores. This threshold is then applied unchanged to the test split.

Reported test metrics are:

- AUROC;
- AUPRC;
- precision;
- recall / sensitivity;
- specificity;
- F1;
- confusion-matrix counts (`tn`, `fp`, `fn`, `tp`).

Cross-validation summaries are produced by `src.training.aggregate_cv_metrics`, which aggregates fold-level test metrics into mean and standard deviation tables.

## Engineered Features

Random Forest, XGBoost, and Isolation Forest use the same feature extractor, implemented in `src/training/extract_features.py` and documented in `docs/features.md`.

The feature vector has 13 values:

| Feature | Summary |
| --- | --- |
| `acc_mag_mean` | Mean acceleration magnitude |
| `acc_mag_max` | Maximum acceleration magnitude |
| `acc_mag_std` | Standard deviation of acceleration magnitude |
| `acc_mag_range` | Range of acceleration magnitude |
| `peak_time` | Relative time of maximum acceleration magnitude |
| `horizontal_mag_mean` | Mean horizontal magnitude from x and z axes |
| `peak_to_peak` | Three-axis peak-to-peak amplitude |
| `jerk_mean` | Mean jerk magnitude |
| `jerk_max` | Maximum jerk magnitude |
| `horizontal_std` | Horizontal-axis variability |
| `acc_std` | Three-axis variability |
| `axis_energy_mean` | Mean squared three-axis acceleration energy |
| `post_peak_delta` | Mean acceleration magnitude after the peak minus before the peak |

Jerk features are scaled by each window's `sampling_rate_hz`, so the feature represents rate of acceleration change per second rather than per sample.

## Supervised Classification Models

### Random Forest

The Random Forest is a supervised ensemble baseline trained on the engineered feature table. It provides a non-deep comparison model that can capture nonlinear relationships between impact, variability, energy, and timing features without using raw sequence order.

Entry point:

```bash
python -m src.training.train_random_forest
```

Default parameters:

| Parameter | Value |
| --- | --- |
| `n_estimators` | `300` |
| `max_depth` | `None` |
| `min_samples_leaf` | `1` |
| `max_features` | `"sqrt"` |
| `class_weight` | `"balanced"` |
| `random_state` | `model_seed` |
| `n_jobs` | `-1` |

The model is trained on the classification processed view. The output score is `predict_proba(X)[:, 1]`, the estimated probability of the fall class. Feature importances are saved to `feature_importance.csv`.

### XGBoost

XGBoost is a boosted-tree supervised classifier trained on the same engineered features as Random Forest. It provides a stronger classical machine-learning baseline because it builds additive decision trees that focus sequentially on errors from previous trees.

Entry point:

```bash
python -m src.training.train_xgboost
```

Default parameters:

| Parameter | Value |
| --- | --- |
| `n_estimators` | `300` |
| `max_depth` | `3` |
| `learning_rate` | `0.05` |
| `subsample` | `0.8` |
| `colsample_bytree` | `0.8` |
| `objective` | `"binary:logistic"` |
| `eval_metric` | `"logloss"` |
| `scale_pos_weight` | `normal_count / fall_count` from the training split |
| `random_state` | `model_seed` |
| `n_jobs` | `-1` |

The output score is `predict_proba(X)[:, 1]`. The imbalance term `scale_pos_weight` is computed separately for each training fold.

### 1D CNN Classifier

The 1D CNN is a supervised deep classifier trained directly on normalized accelerometer windows. It applies temporal convolution filters over the raw sequence, allowing the model to learn local impact and movement patterns without manually engineered summaries.

Entry point:

```bash
python -m src.training.train_cnn1d
```

Architecture in `src/models/cnn1d.py`:

```text
Input: batch x T x 3
Permute to batch x 3 x T
Conv1d(3, 32, kernel_size=5, padding=2)
BatchNorm1d(32)
ReLU
MaxPool1d(kernel_size=2)
Conv1d(32, 64, kernel_size=3, padding=1)
BatchNorm1d(64)
ReLU
AdaptiveAvgPool1d(1)
Flatten
Linear(64, 64)
ReLU
Dropout(0.3)
Linear(64, 1)
```

Default training parameters:

| Parameter | Value |
| --- | --- |
| `epochs` | `30` |
| `batch_size` | `64` |
| `learning_rate` | `1e-3` |
| `weight_decay` | `0.0` |
| `patience` | `8` |
| `optimizer` | Adam |
| `loss` | `BCEWithLogitsLoss` |
| `pos_weight` | `normal_count / fall_count` from the training split |
| `device` | `auto` by runbook |

The model returns a single logit. During evaluation this is converted to a fall score with the sigmoid function.

### LSTM Classifier

The LSTM classifier is a supervised recurrent model trained on normalized raw windows. It processes the sequence in temporal order and uses the final hidden state as a learned summary of the window.

Entry point:

```bash
python -m src.training.train_lstm_classifier
```

Default architecture in `src/models/lstm_classifier.py`:

```text
Input: batch x T x 3
LSTM(input_size=3, hidden_size=64, num_layers=1, batch_first=True)
Take final hidden state
Dropout(0.3)
Linear(64, 32)
ReLU
Dropout(0.2)
Linear(32, 1)
```

Default training parameters:

| Parameter | Value |
| --- | --- |
| `epochs` | `30` |
| `batch_size` | `64` |
| `learning_rate` | `1e-3` |
| `weight_decay` | `0.0` |
| `patience` | `8` |
| `hidden_size` | `64` |
| `dense_units` | `32` |
| `dropout` | `0.3` |
| `dense_dropout` | `0.2` |
| `num_layers` | `1` |
| `optimizer` | Adam |
| `loss` | `BCEWithLogitsLoss` |
| `pos_weight` | `normal_count / fall_count` from the training split |

The output logit is passed through a sigmoid to obtain the fall score.

## TSAD Models

### Isolation Forest

Isolation Forest is the classical anomaly-detection baseline. It is trained only on normal training windows using the same engineered features as the shallow supervised classifiers. The method isolates unusual samples through random feature splits; windows that are easier to isolate are treated as more anomalous.

Entry point:

```bash
python -m src.training.train_isolation_forest
```

Default parameters:

| Parameter | Value |
| --- | --- |
| `n_estimators` | `300` |
| `contamination` | `"auto"` |
| `max_samples` | `"auto"` |
| `max_features` | `1.0` |
| `random_state` | `model_seed` |
| `n_jobs` | `-1` |

The anomaly score is `-model.decision_function(X)`, so larger values indicate more anomalous windows. The final operating threshold is still chosen on validation F1, not from the Isolation Forest contamination setting.

### Dense Autoencoder

The Dense autoencoder is a neural reconstruction baseline. It flattens each normalized accelerometer window into a vector, compresses it through a latent layer, and reconstructs the original vector. Because it ignores explicit temporal order after flattening, it is best interpreted as a simple reconstruction baseline.

Entry point:

```bash
python -m src.training.train_dense_ae
```

Default architecture in `src/models/dense_ae.py`:

```text
Input: batch x T x 3
Flatten to batch x (T * 3)
Linear(input_dim, 128)
ReLU
Dropout(0.1)
Linear(128, 64)
ReLU
Dropout(0.1)
Linear(64, 16)
ReLU
Linear(16, 64)
ReLU
Linear(64, 128)
ReLU
Linear(128, input_dim)
Reshape to batch x T x 3
```

Default training parameters:

| Parameter | Value |
| --- | --- |
| `epochs` | `30` |
| `batch_size` | `64` |
| `learning_rate` | `1e-3` |
| `weight_decay` | `0.0` |
| `patience` | `8` |
| `latent_dim` | `16` |
| `hidden_dims` | `(128, 64)` |
| `dropout` | `0.1` |
| `optimizer` | Adam |
| `loss` | Mean squared reconstruction loss |

The anomaly score is the mean squared reconstruction error over time steps and axes.

### CNN1D Autoencoder

The CNN1D autoencoder is a convolutional reconstruction model trained on normal windows only. Its encoder compresses local temporal patterns using Conv1D layers and pooling; its decoder upsamples the representation back to the original sequence length.

Entry point:

```bash
python -m src.training.train_cnn1d_ae
```

Architecture in `src/models/cnn1d_ae.py`:

```text
Input: batch x T x 3
Permute to batch x 3 x T
Encoder:
  Conv1d(3, 32, kernel_size=5, padding=2)
  BatchNorm1d(32)
  ReLU
  MaxPool1d(kernel_size=2, ceil_mode=True)
  Conv1d(32, 64, kernel_size=3, padding=1)
  BatchNorm1d(64)
  ReLU
  MaxPool1d(kernel_size=2, ceil_mode=True)
  Conv1d(64, 64, kernel_size=3, padding=1)
  ReLU
Decoder:
  Upsample(scale_factor=2, mode="linear")
  Conv1d(64, 32, kernel_size=3, padding=1)
  BatchNorm1d(32)
  ReLU
  Upsample(scale_factor=2, mode="linear")
  Conv1d(32, 3, kernel_size=3, padding=1)
Match reconstructed length to input length
Permute back to batch x T x 3
```

Default training parameters:

| Parameter | Value |
| --- | --- |
| `epochs` | `30` |
| `batch_size` | `64` |
| `learning_rate` | `1e-3` |
| `weight_decay` | `0.0` |
| `patience` | `8` |
| `optimizer` | Adam |
| `loss` | Mean squared reconstruction loss |

The anomaly score is the mean squared reconstruction error over time steps and axes.

### LSTM Autoencoder

The LSTM autoencoder is a sequence reconstruction model trained on normal windows only. The encoder reads the input sequence and maps the final hidden state to a compact latent representation. The decoder repeats this latent representation across the sequence length and reconstructs the triaxial accelerometer signal.

Entry point:

```bash
python -m src.training.train_lstm_ae
```

Default architecture in `src/models/lstm_ae.py`:

```text
Input: batch x T x 3
Encoder LSTM(input_size=3, hidden_size=64, num_layers=1, batch_first=True)
Take final hidden state
Dropout(0.2)
Linear(64, 32)
ReLU
Repeat latent vector T times
Decoder LSTM(input_size=32, hidden_size=64, num_layers=1, batch_first=True)
Linear(64, 3) at each time step
```

Default training parameters:

| Parameter | Value |
| --- | --- |
| `epochs` | `30` |
| `batch_size` | `64` |
| `learning_rate` | `1e-3` |
| `weight_decay` | `0.0` |
| `patience` | `8` |
| `hidden_dim` | `64` |
| `latent_dim` | `32` |
| `num_layers` | `1` |
| `dropout` | `0.2` |
| `optimizer` | Adam |
| `loss` | Mean squared reconstruction loss |

The anomaly score is the mean squared reconstruction error over time steps and axes.

## Common Deep-Learning Training Details

All deep models use PyTorch and the shared helpers in `src/training/deep_utils.py`.

Common settings:

| Setting | Value |
| --- | --- |
| Optimizer | Adam |
| Default epochs | `30` |
| Default patience | `8` |
| Default learning rate | `1e-3` |
| Default weight decay | `0.0` |
| Default workers | `0` |
| Device selection | `auto`, `cpu`, or `cuda`; `auto` uses CUDA if available |
| Seed handling | Python, NumPy, and PyTorch seeds set from `model_seed` |

Model selection during training uses validation F1. After each epoch, the model is scored on the validation split, the best F1 threshold is selected on that validation score distribution, and the model state with the best validation F1 is retained. Training stops early after `patience` epochs without improvement.

Classifier loss:

```text
BCEWithLogitsLoss(pos_weight = normal_training_windows / fall_training_windows)
```

Autoencoder loss:

```text
MSE(reconstruction, input)
```

## Models Not in the Current Main Setup

The current repository does not include active training entry points for SVM, VAE, LSTM-VAE, TranAD, or a signal-threshold baseline. These can be discussed as possible future extensions, but they should not be described as part of the current study setup unless they are implemented, run, and added to the result trackers.
